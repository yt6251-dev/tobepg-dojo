# TobePG — QA から AI駆動開発エンジニアへ 12週間計画

作成 2026-09-19
期間 2026-09-20（日）〜 2026-12-13（日）の12週
前提 週15時間（曜日と時間帯は決めない。週の合計だけ守る）

---

## 1. ゴールの置き方

「シニアプログラマー」を年数で測る定義は12週では届かない。届くのはこの4つで これを「案件で通用するレベル」と呼ぶ。

1. AI駆動開発の案件票に書いてある「設計・実装・レビュー」を自分で回せる
2. AIが止まったとき 間違えたときに自分で読んで直せる
3. 2時間のコーディング試験と設計面接を通る
4. 公開できる実績が3つある（製品1 改修事例1 OSSのPR1）

市場の案件票（Offers・レバテック）は必須に「設計・開発経験5年以上」と書いている。年数では勝てないので **公開された実績と選考の通過で上書きする**。これが12週の狙い。

## 2. 手持ちの資産と埋めるもの

| 既にあるもの | 埋めるもの |
|---|---|
| QA 12年。テスト設計 リスク判断 レビューの目 | 自分の手で書く量。いまはAIが書いたものを読んで直している |
| AIに書かせた TypeScript 6,100行の API と Flutter アプリを実運用 | 型 非同期 エラー処理を**説明できる**深さ |
| Claude Code のマルチエージェント運用 受け入れ基準の数値化 | データモデルと API の**設計を自分で決める**経験 |
| 脆弱性調査と修正 8件 | 本番相当の運用（CI/CD 環境分離 監視 マイグレーション） |
| Playwright 導入 Node のテストハーネス自作 | チーム前提の Git（ブランチ PR レビュー rebase） |
| 仕様書と観点表をAI可読に書く力 | 選考の形式（時間制限のある実装 設計の口頭説明） |

右側は全部「一人で製品を作って公開する」過程で埋まる。だからカリキュラムの中心は製品作りで 座学はそれを支える分だけにする。

## 3. 主戦場を1つに絞る

**TypeScript / Node / Next.js / Postgres** に絞る。理由は3つ。

- 案件票で一番多い組み合わせ（Offers の AI駆動開発案件は TypeScript React Next.js Node が主）
- すでに teciora.com が Next.js 15 で 元町Cal の API が TypeScript。ゼロからではない
- Flutter は Mood-Ring Weather で維持できている。広げるより深める

Flutter は週1時間の保守だけに落とす。Python は触らない。

## 4. AIの使い方は3モードで分ける

これが一番大事な運用ルール。**AIを使うほど自分で書けなくなる**のを防ぐ。

| モード | 使う場面 | ルール |
|---|---|---|
| 先生 | 概念の説明 他人のコードの読み解き エラーの意味 | 制限なし。ただし説明を聞いたら自分の言葉で書き直す |
| ペア | 製品の実装 リファクタリング | AIに書かせたら**自分で説明できるか**を確認してから採用。説明できなければ自分で書き直す。これは自分の面接原則「AIの自己申告は事実ではない」を自分自身に向けたもの |
| オフ | 毎日のドリル 手書き課題 デバッグ課題 コーディング試験の練習 | AIを閉じる。15分考えて動かなければメモして翌日に先生モードで聞く |

オフの時間は**週の3割**を下回らせない（15時間なら4.5時間）。ここが崩れると12週後も「AIが書いたものを読む人」のまま。

## 6. 週15時間が取れないとき

10時間の週は次の順で削る。

1. 座学（教材を読む時間）を半分に
2. 発信（週次の記事）をメモ書きに
3. OSS 貢献を後ろへ

削ってはいけないもの: **毎日のドリル30分** と **製品作り**。この2つが止まると計画が止まる。
