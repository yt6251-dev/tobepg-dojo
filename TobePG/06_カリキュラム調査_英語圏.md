# 06 カリキュラム調査 — 英語圏の優れた学習カリキュラムは何をしているか

調査日 2026-09-19
目的 Dojo（課題→採点→合格/不合格で進むWebアプリ）の設計に 英語圏で実績のあるカリキュラムの型を借りる

---

## 1. 結論

英語圏で評価の高いカリキュラムは 形は違っても**同じ6つの型**を持っている。Dojo はこの6つをそのまま実装すればよい。

| 型 | 採用している所 | Dojo での実装 |
|---|---|---|
| 1. 順番が固定で 前の課題を通さないと次が開かない | Full Stack Open / Exercism / boot.dev / Hack Reactor | `curriculum.json` の前提関係 |
| 2. 合格か「まだ」か。落第は無い。「まだ」の後は待機期間 | Launch School（Mastery-Based Learning） | 不合格を「Not Yet」と表示し 再挑戦は翌日以降 |
| 3. Git に push すると自動でテストが走って判定 | Codecrafters / Full Stack Open / Exercism | `pnpm grade` と CI |
| 4. 道具を自分で作り直して深さを得る | Codecrafters（Redis/Git/SQLite を作る）/ Software Design by Example（テストランナーを作る） | 第7〜10週の「採点器を自作する」課題 |
| 5. 前半は基礎の詰め込み 後半は製品と職探し | Hack Reactor（1〜6週 Junior / 7〜12週 Senior） | Phase 1〜2 と Phase 3 の分け方はこのまま |
| 6. AI時代の評価は 口頭説明 プロセスの記録 コードレビュー | 2026年8月の論文（後述） | 「AIに書かせた3か所を自分で説明」と週次記録 |

そして一番重要な補正が1つ。**時間の目安**。Hack Reactor は12週で65〜75時間/週 = 約800時間。事前課程も90〜120時間ある。こちらは15時間/週 = 180時間で **ブートキャンプの4分の1**。12週で全部はできない。QAの経験と製品2つがあるぶん基礎は飛ばせるので **範囲を絞れば「案件で通用する」に届く**。絞り方は §5。

## 2. 調べたカリキュラムと 借りるところ

### Full Stack Open（ヘルシンキ大学 無料）★背骨に使う

- Part 0〜13。Part 3 Node/Express Part 4 Express のテスト Part 5 React のテストと E2E Part 9 TypeScript Part 11 CI/CD Part 12 コンテナ Part 13 リレーショナルDB
- 演習は **GitHub に上げて提出システムに登録**。盗用検出あり。1 Part あたり15〜20時間。Part 0〜7 で150問以上解くと7単位。**無料の修了証**が出る
- 「Part n を十分理解する前に n+1 に進むのは意味がない」と明記。順番固定の思想
- 2026年3月の改訂で Cypress が外れ E2E は Playwright に。ユニットは Vitest
- URL https://fullstackopen.com/en/

**借りるもの**: 演習そのもの。Part 3・4・9・11・13 の演習を Dojo の課題として取り込む（CC BY-NC-SA なので個人利用は問題ない）。自分で課題を全部書く必要がなくなる。

### Launch School（有料 月額）★採点の思想を借りる

- **Mastery-Based Learning**。全コースに評価があり 通らないと進めない。筆記 ライブの1対1コーディング面接 持ち帰り課題
- 「落第」ではなく **「Not Yet」**。Not Yet の後は**必須の待機期間**がある。合格率は5〜7割
- 「どれだけ時間がかかったかは関係ない。そのトピックを本当に知っているかだけ」
- URL https://launchschool.com/courses ／ 解説 https://public.launchschool.com/mastery

**借りるもの**: Not Yet と待機期間。すぐ再提出できると「テストが通るまで当てずっぽうで直す」になる。翌日以降にすると 一晩考えるか先生モードで聞くしかなくなる。

### Codecrafters（有料 無料枠あり）★深さの層

- 「Build Your Own X」。Redis Git SQLite HTTP サーバー DNS Docker Kafka を**自分で作り直す**。Google・OpenAI・Vercel のエンジニアが使う
- 自分の IDE で書いて **git push すると即判定**。段階（stage）ごとにテストが通ると次へ。1本に数週間かかる
- TypeScript 対応の課題あり（HTTP サーバーなど）
- URL https://codecrafters.io/ ／ 無料のカタログ https://github.com/codecrafters-io/build-your-own-x

**借りるもの**: push で判定 と 段階分け。第9〜10週に HTTP サーバーを1本やると「Node の裏側が分かっている人」になれる。時間が無ければ後回し。

### Software Design by Example（Greg Wilson 無料公開）★Dojo の採点器そのもの

- 「小さな版の道具を作って 経験者の考え方を知る」本。**テストフレームワーク** ファイルバックアップ 正規表現マッチャ ブラウザのレイアウトエンジン 小さなコンパイラを **JavaScript で**作る
- 各章に演習（数行〜1日分）。本文は CC BY で無料
- URL https://github.com/gvwilson/sdxjs

**借りるもの**: 「テストランナーを作る」章をそのまま Dojo の課題にする。Dojo の採点器を自分で書くことになり TestLens（空テスト検出）の土台になる。

### The Odin Project（無料）

- HTML/CSS/JS/Git/Node/React を製品作りで学ぶ。読んで作る形式。修了生の就職実績が高いとされる
- URL https://www.theodinproject.com/

**借りるもの**: 課題文の書き方（何を作るか 何ができれば合格か を先に書く）。中身は基礎すぎるので課題は取り込まない。

### boot.dev（有料 月額25〜30ドル）

- 24モジュールを順番に。XP レベル ストリーク リーダーボード。Python → Go → SQL → C。初心者で約12か月
- URL https://www.boot.dev/tracks/backend

**借りるもの**: ストリーク（連続日数）だけ。毎日のドリルの継続に効く。XP やレベルは自分一人では空回りするので入れない。

### Hack Reactor（有料 12週フルタイム）★時間の物差し

- 事前課程 90〜120時間 → **1〜6週 Junior**（2日単位のスプリント ペアプロ。データモデリング DS&A React Node DB 認証）→ **7〜12週 Senior**（キャプストーン2本 コードレビュー テスト デプロイ 履歴書 面接）
- 週65〜75時間

**借りるもの**: 前半後半の分け方 と 時間の現実。§1 の補正。

### Exercism（無料）

- 言語ごとの **概念ツリー**。概念課題を通すと次の概念と関連する練習課題が開く。CLI で `download` → 解く → `submit`。メンターに見てもらえる
- URL https://exercism.org/tracks/typescript

**借りるもの**: 概念ツリーの見せ方（Dojo のダッシュボードの地図）。第1〜3週のドリルはここをそのまま使う。

### Teach Yourself CS / OSSU（無料）

- 9科目を数年かけて。ただし **近道**が書いてある: 「独学とブートキャンプ出身者にとって費用対効果が最も高いのは2冊。Computer Systems: A Programmer's Perspective と Designing Data-Intensive Applications」
- URL https://teachyourselfcs.com/ ／ https://github.com/ossu/computer-science

**借りるもの**: DDIA の第1〜3章と第7章だけ（既に 01_カリキュラム に入れてある）。CS:APP は C とアセンブリなので12週では触らない。

### roadmap.sh（無料）

- 2026年のフルスタックに必要な5つ: フロントの枠組み1つを深く / TypeScript か Python のバックエンド / API 設計と認証 / **AI支援開発の習熟** / 問題の分解と設計判断。毎日やって4〜8か月で就職水準
- URL https://roadmap.sh/typescript ／ https://roadmap.sh/full-stack

**借りるもの**: 5つの軸。01_カリキュラム のトラック A〜D と一致しているので変更なし。

## 3. AI時代の評価法（2026年8月の論文）

「Mapping the Emerging Curriculum for AI-Assisted Software Engineering via Syllabus Analysis」（arXiv 2608.05898）。大学のAI支援ソフトウェア工学の科目23件のシラバスを分析したもの。

学習目標で多かったもの
1. 人とAIの協働（AIの文脈を管理する）
2. AIツールで作る
3. **AIが作ったものを正しさと信頼性で評価する**

評価の方法
- プロジェクト/キャプストーンが成績の中央値50%
- コーディング課題 20%
- **監督付き試験は14科目中3科目だけ**
- 個人の学習を測るために **プロセスの記録 コードレビュー 口頭での説明** を使う

使われている道具: Claude Code が最多（9科目中6）。次に Cursor と Copilot

設計者への勧め
- AIの実践は **既存のソフトウェア工学の基礎の上に重ねる**。道具の使い方だけ教えない
- 個人の評価は プロセスログ コードレビュー 口頭の防御 で補強する

**Dojo への反映**: 「AIに書かせた3か所を自分で説明する」は論文の言う口頭の防御そのもの。`05_進捗チェックリスト` の週次記録がプロセスログ。TestLens の「AIが作ったテストの質を評価する」は学習目標3番と一致する。方向は合っている。

関連して 業界側の数字: コードレビューに使う時間が91%増 PR のサイズが154%増。面接は「AIが書いたコードをデバッグさせる」方向に動いている。**レビューとデバッグの課題を増やす根拠**になる。

## 4. 学習科学から借りる3つ

数百の学習研究を見直した Dunlosky らの評価で **効果が最も高い2つ**は「想起練習（テストされること）」と「分散練習（間隔を空ける）」。加えて「交互練習（違う種類を混ぜる）」がまとめ練習より長期の定着に効く。

| 原則 | Dojo での実装 |
|---|---|
| 想起練習 | 説明を読んでから書くのではなく **先に書かせてテストで返す**。解説は後 |
| 分散練習 | 合格した課題を **2週間後に再出題**する（少し変えて）。Not Yet の待機期間も分散になる |
| 交互練習 | 1週の中で 型 / SQL / Git を混ぜる。月曜は型だけ 火曜は SQL だけ にしない |

「能力の端で 即時のフィードバックを得ながら練習する」が最速。テストが即時のフィードバック。課題の難度は「7割は通るが3割は Not Yet」を狙う（Launch School の合格率と同じ水準）。

## 5. 12週に収める絞り方

180時間で何をやるか。Hack Reactor の Junior 6週分（約400時間）を **QA 経験と製品2つで飛ばせるもの**を除いて圧縮する。

| Hack Reactor が扱うもの | 扱い | 理由 |
|---|---|---|
| Browser apps / jQuery / AJAX | 飛ばす | 古い。Next.js で足りる |
| ES6 / React / State Management | Dojo のダッシュボード作りで学ぶ | 座学にしない |
| Data Structures / Complexity | ドリルだけ（毎日30分） | 面接の最低線 |
| Node / Server-side / Databases / Auth | **中心**。FSO Part 3・4・9・13 | 案件票の必須 |
| Testing / Code review / Deployment | **中心**。FSO Part 5・11 + 自分の得意 | AI時代に価値が上がっている |
| Agile / Documentation | 既にある（AGENTS.md 仕様駆動） | 一般化して文書にするだけ |
| Resume / Interview | 第11〜12週 | `interview/` に材料がある |

### 背骨の割り当て（03_スケジュール への反映案）

| 週 | Dojo の課題の出どころ | 目安時間 |
|---|---|---|
| 1〜2 | Exercism TypeScript（ドリル）+ FSO Part 9 TypeScript の演習 + 自分の index.ts を読む | 30h |
| 3 | FSO Part 3 Node/Express の演習 + SQLBolt | 15h |
| 4 | FSO Part 4 Express のテスト + P3 手書き3本 | 15h |
| 5〜6 | Dojo のダッシュボードを Next.js で作る（React はここで学ぶ）+ FSO Part 13 リレーショナルDB | 30h |
| 7〜8 | Software Design by Example「テストフレームワーク」の章 → Dojo の採点器を自作 + FSO Part 11 CI/CD | 30h |
| 9〜10 | 採点器に空テスト検出を足す（TestLens）+ FSO Part 5 E2E（Playwright）+ 任意で Codecrafters HTTP サーバー | 30h |
| 11〜12 | 実装試験3回 設計面接 レビュー面接 応募 | 30h |

合計 180h。FSO の演習を取り込むことで **課題を書く手間の半分以上が消える**。自分で書くのは 元町Cal 由来の課題（読む 手で書き直す 認証の後付け）と Dojo 自体の拡張課題。

## 6. Dojo の採点ルール（調査結果から決めたもの）

1. **Not Yet 方式**。不合格は表示しない。「まだ」と出して 再挑戦は翌日以降
2. **push で採点**。ローカルで `pnpm grade` を叩けるが 記録に残るのは CI が通したものだけ
3. **前提関係で解錠**。合格した課題の次だけ開く。地図はExercism の概念ツリーの見せ方
4. **口頭の防御**。AIに書かせた課題は 合格後に「3行で説明」を入力しないと完了にならない。入力は記録に残す
5. **2週間後の再出題**。合格した課題を少し変えて再提示。通らなければ元の課題を Not Yet に戻す
6. **難度の目安**。週の合格率が9割を超えたら難度を上げる。5割を切ったら下げる
7. **ストリーク**。毎日のドリルだけ連続日数を表示。それ以外の gamification は入れない
