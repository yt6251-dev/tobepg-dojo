# 05 型の穴を1つ塞ぐ（証拠つき課題）

AI: **ペア**
目安: 2時間

## 課題

**自分が関わっている TypeScript のコードベース**から `any`（または実質 `any` の `as` キャスト）を1か所選び 正しい型に置き換える。

対象の候補
- `teciora_HP/teciora-web/`（Next.js 15 + TypeScript）
- いまの案件のコード（公開しないので `--note` に書く内容だけ一般化する）
- この Dojo 自身（`scripts/grade.mjs` を TypeScript 化する のも可）

## 手順

1. 候補を探す。`any` そのものより **`as` で黙らせている箇所**のほうが価値が高い

   ```sh
   grep -rn ": any\|as any\|<any>" --include="*.ts" --include="*.tsx" . | grep -v node_modules
   ```

2. **権限・お金・外部入力のいずれかに関わる**ものを1つ選ぶ。表示だけの箇所は避ける
3. 置き換える前に その箇所の**現在の振る舞いを確かめるテスト**を書く（無ければ新規に）
4. 正しい型に置き換える。`tsc --noEmit` を通す
5. テストが通ることを確認する
6. ブランチ `dojo/05-type-hole` にコミットする

## 合格条件

```sh
npm run grade -- 05 \
  --evidence "<コミットハッシュ または PR の URL>" \
  --note "何を何に変えたか（1行）" \
  --explain "なぜその型が正しいと言えるか。3文以上"
```

`--explain` には **「この型でないとどう壊れるか」** を1文入れること。型を狭めた結果 どの入力が弾かれるようになったかを言えれば合格。

## なぜこれか

`any` は「型チェックを諦めた印」で そこだけコンパイラが守ってくれません。1か所塞ぐ作業を通して **型注釈を読む → 実際の値を確かめる → 正しい型を決める** という流れが身につきます。

課題01〜04 は与えられた型を満たす練習でした。ここからは **自分で型を決める**練習に入ります。第2週以降の課題と 第7週の静的解析（採点器の自作）につながります。
